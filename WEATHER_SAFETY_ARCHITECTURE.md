# BoxSafe Weather Safety Architecture

## Purpose

Add a route-aware weather safety layer for commercial box trucks without mixing weather logic into the low-bridge database.

BoxSafe should evaluate hazards along the planned route and at the expected arrival time for each route segment, not only at the driver's current location.

## Hazard classes

- SNOW
- FREEZING_RAIN
- SLEET
- ICE_RISK
- HEAVY_RAIN
- FLOOD_RISK
- HIGH_WIND
- LOW_VISIBILITY
- EXTREME_COLD
- EXTREME_HEAT

## Route-aware model

For each route segment BoxSafe should retain:

- segment start/end coordinates
- expected arrival time window
- weather source and forecast issue time
- hazard type
- severity
- confidence
- expiration time
- truck profile factors used in the assessment
- recommended action
- source record identifier

## Truck-specific factors

Weather risk should be adjusted for:

- vehicle height
- vehicle length
- vehicle weight
- estimated load state when known
- axle count
- exposed bridge/elevated-road segments when known

High-wind alerts are especially important for tall/light box trucks, but BoxSafe should not infer a precise rollover threshold unless a validated engineering rule or authoritative source supports it.

## Severity states

- INFO: weather may affect comfort or travel time.
- CAUTION: meaningful deterioration is expected.
- HIGH_RISK: route segment has conditions that may materially affect commercial-vehicle safety.
- DO_NOT_PROCEED: reserved for authoritative closures, explicit legal restrictions, or a validated BoxSafe safety rule with sufficiently strong evidence.

## Freshness rules

Every weather record must include:

- source
- issuedAt
- validFrom
- validUntil
- fetchedAt

Expired forecasts must not continue generating active warnings.

## Recommended data-source layers

1. National Weather Service or other authoritative forecast/alert source.
2. State 511 / DOT road-condition and closure feeds.
3. Road-sensor or commercial weather feeds where licensed.
4. User reports only as unverified observations until corroborated.

## Driver-facing behavior

A weather warning should explain:

- what the hazard is
- where it begins
- approximately when the truck is expected to reach it
- severity
- source freshness
- suggested action

Example:

"WINTER WEATHER AHEAD — freezing precipitation forecast on this route segment in approximately 38 miles. Conditions may be hazardous for this truck profile. Review alternate route."

## Auditability

Every safety warning generated by this layer should emit a Safety Event using the BoxSafe safety-event schema so the company can later demonstrate what warning was shown, when, where, and from which data source.
